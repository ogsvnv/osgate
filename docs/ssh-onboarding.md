# Настройка SSH-авторизации через веб-панель OSGate

При ошибке **`PermissionDenied`** удалённый SSH-сервер не принимает
приватный ключ, настроенный у OSGate. Это не связано с логином
администратора веб-панели.

## Как настроить доступ из OSGate

1. Откройте веб-панель по локальному адресу `/login`.
2. Перейдите в **SSH-серверы** и нажмите **Настроить SSH-доступ**
   напротив нужного сервера.
3. Проверьте имя хоста, порт и пользователя SSH.
4. Введите **пароль этого SSH-пользователя** и поставьте галочку
   подтверждения установки публичного ключа.
5. Нажмите **Установить ключ и проверить SSH**.

OSGate возьмёт публичную часть настроенного SSH-ключа, подключится
к удалённому серверу с временно введённым паролем и добавит ключ
в `~/.ssh/authorized_keys`, **не удаляя другие ключи**.
Затем приложение выполнит привычную проверку SSH и TCP forwarding.
При повторном запуске уже записанный ключ не дублируется.

При добавлении *нового* сервера используется аналогичная галочка
**«Настроить SSH-доступ через пароль при добавлении»**.

### Условия безопасности

- Первоначальный вход должен быть **разрешён удалённым SSH-сервером**.
  Если `PasswordAuthentication no`, используйте уже разрешённый ключ
  или настройте `authorized_keys` другим административным способом:
  OSGate не может обойти SSH-авторизацию.
- SSH **host key обязательно проверяется** по существующему
  `known_hosts`. Приложение не отключает проверку fingerprint
  и не принимает новый ключ сервера вслепую.
- Приватный ключ и `known_hosts` должны находиться в `SSH_DIRECTORY`,
  заданном конфигурацией (обычно `/ssh` в Docker).
- **Пароль SSH не сохраняется** в SQLite, журнал, `.env` или
  диагностические отчёты. Он используется только в одном запросе;
  предусмотрено ограничение количества попыток.
- Новая операция требует успешного входа администратора и CSRF-проверки.
  Не открывайте административную панель по HTTP в интернете:
  используйте SSH-туннель или HTTPS reverse proxy.
- Не изменяются конфигурация `sshd_config`, firewall, пароли,
  действующие ключи SSH или пользовательские права.

### Если пароль не принимается

Проверьте `username`, `port`, пароль и настройки
`PasswordAuthentication`/`KbdInteractiveAuthentication` на
удалённом сервере. В некоторых инфраструктурах парольный вход
запрещён по политике безопасности — **не включайте его ради OSGate**.
В таком случае разместите публичную часть ключа OSGate через
уже авторизованный административный SSH-доступ, а затем нажмите
**Проверить подключение**.

Если публичный ключ установлен, но всё ещё не работает TCP forwarding,
на SSH-сервере проверьте `AllowTcpForwarding yes` и доступность
`HEALTH_TEST_HOST:HEALTH_TEST_PORT` из удалённой сети.
