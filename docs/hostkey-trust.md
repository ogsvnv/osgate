# Подтверждение подлинности SSH-сервера в OSGate

## Ошибка HostKeyNotVerifiable

Это значит, что OSGate не доверяет ключу удалённого SSH-сервера.
Не отключайте SSH host-key verification. Эта защита предотвращает
подключение к подменённому серверу.

## Для существующего SSH-сервера

1. Откройте **SSH-серверы** и нажмите **Проверить и подтвердить ключ SSH-сервера**.
2. OSGate получит SSH host key и покажет его SHA256 fingerprint.
   **Это пока непроверенный ключ!**
3. На самом удалённом сервере откройте консоль или используйте другой
   независимый уже доверенный административный канал. Сверьте fingerprint,
   например: `sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`.
   У сервера может быть несколько host-key алгоритмов: сравнивайте
   соответствующий ключ. При несовпадении НИЧЕГО не подтверждайте.
4. Только после независимой проверки скопируйте/введите отпечаток в поле
   и подтвердите действие.
5. OSGate заново получает ключ и сравнивает его с введённым отпечатком.
   При совпадении сохраняет новый файл known_hosts, привязанный к
   конкретному хосту и порту, и повторно проверяет подключение.

Если после успешного подтверждения ключа появилась `PermissionDenied`,
откройте **Настроить SSH-доступ** — это отдельная ошибка авторизации
SSH-пользователя. Если соединение авторизуется, но не работает выход
в интернет, проверьте TCP forwarding и `HEALTH_TEST_HOST`.

## Для нового SSH-сервера

На странице **SSH-серверы → Добавить SSH-сервер** укажите хост, порт
и пользователя. Нажмите **Показать SHA256-отпечаток**, независимо
проверьте его и введите в поле подтверждения. После сохранения OSGate
будет использовать этот ключ для проверки сервера. Если одновременно
нужно установить пользовательский SSH-ключ, используйте галочку
**«Настроить SSH-доступ через пароль при добавлении»**.

## Хранение и безопасность

- Основной SSH-каталог `/ssh` в Docker остаётся read-only.
- Новые host keys помещаются в `/data/ssh-hostkeys` (можно изменить
  через `SSH_HOSTKEYS_DIRECTORY`). Это отдельный каталог в постоянном
  Docker volume с правами `0700`; файлы создаются с `0600`.
- Приватные SSH-ключи, пароли и исходный `known_hosts` не меняются.
- Нельзя принять ключ без CSRF, авторизации администратора и явного
  SHA256-отпечатка. При смене ключа происходит повторная проверка.
- Подтверждение ключа **не означает** успешную авторизацию SSH-пользователя.
- Защитите административную веб-панель SSH-туннелем или HTTPS.
